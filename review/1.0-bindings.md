# 1.0 binding engine review

Reviewed: Macros, NativeBars, AvailabilityEngine, Engine, CurrentBindings, API, Protection, and their regression fixtures. Scope includes native placement, conditional casts, future spell learning, exact ranks, macro ownership, rollback, account/character scopes, addon button lookup, and default recovery.

## Findings resolved

- Future preset spells and talents previously allocated placeholder macros even though the addon can populate native slots on learning. They now reserve empty slots with stable key assignments. Learning, higher ranks and talent removal update only still-owned positions outside combat; personal replacements detach from maintenance.
- Learned simple talents, exact ranks, self-only spells, and ordinary spells with no effective targeting/form conditions now use native spell actions. Conditional targeting, non-toggle forms, combos, pet/overflow behavior, and equipment-slot macros remain where their semantics require them.
- An old `allowAccountMacros=true` could create shared account macros. New macro creation and preflight budgets are now character-only, including old/imported settings. Existing exact owned account macros are reused for migration; unrelated account macros remain untouched. No automatic destructive migration occurs.
- All native plans participate in learning maintenance. Conditional macros whose content remains a macro keep the existing in-place, fingerprint-checked transaction; empty/spell/macro transitions use the bounded native-slot transaction. This preserves full-bank form maintenance and avoids unnecessary key writes. Rank-only metadata updates retain the same macro identity and count.
- Current view now resolves live native action attributes from known Bartender4 and Dominos action button names for `LeftButton`, `Keybind`, and `HOTKEY` click bindings. No slot is inferred from the number in a third-party button name; non-action/missing frames and unknown addons fall back to the original binding description.
- Added `Engine:RestoreDefaults()`: complete named backup first, load Blizzard defaults, save to character bindings, disable prior automatic layout ownership, clear stale recovery flags, and retain bar contents/personal macros. Combat/busy states reject before mutation; failure uses bounded rollback. Named backup restores the previous configuration.
- Changed the new-settings default for automatic utility form cancellation to off. This makes ordinary cast behavior native and keeps complete Era catalogs within a 30-slot character macro bank. Existing explicit preferences survive. A separate cancel-form key and opt-in auto-cancel remain.

## Capacity evidence

The new `v1_full_era_*` tests use the real mocked 30-character-slot limit, an empty account bank, Era capabilities, all catalog spells learned, and complete spell coverage. They actually apply each plan and inspect installed native actions. This is a conservative stress fixture: it includes talents that cannot normally coexist.

| Class | Unique macros | Character limit |
|---|---:|---:|
| Druid | 29 | 30 |
| Mage | 9 | 30 |

| Rogue | 4 | 30 |
| Hunter | 21 | 30 |
| Priest | 24 | 30 |

Opting into auto-cancel on the all-learned Druid fixture requests 37 macros and correctly fails preflight with no writes. Limits are detected at runtime; personal occupied slots and smaller client banks can also make an advanced preset exceed capacity. The app never overwrites personal macros or silently enables account overflow.

Other legacy full-catalog behavioral tests explicitly use a larger test-only character bank, rather than account overflow, to isolate unrelated transaction and UI behavior. Dedicated macro-capacity tests and the new nine-class matrix retain real limits.

## Validation

New cases cover default reset/undo, unchanged account bindings and native contents, failed-save rollback, combat rejection, stale recovery flags, legacy overflow rejection, live addon slot mapping and non-action rejection, macro-free future slots, and higher-rank heal metadata without replacing its macro. Existing tests cover bounded workers, combat pause/resume, personal macro edit/delete/reindex races, native placement rollback, shared talent variants, hidden mouse controls, and reload restoration.

The final in-progress full run ended 492/493 because one legacy auto-cancel test still assumed the former default. That test now explicitly enables the option and passes independently, as does the conditional-targeting test. A further focused rank-metadata regression passes. Parent release packaging owns the final authoritative suite count.

## Remaining live-client verification

Mock tests cannot certify protected game input, taint, server casting rules, display texture/font behavior, or every third-party addon state driver. Bartender4's upstream ActionBars.lua confirms native mapping, `BT4Button` naming and `Keybind` migration: https://raw.githubusercontent.com/Nevcairiel/Bartender4/master/ActionBars.lua . Dominos upstream source retrieval failed in this environment; its narrow attribute-based adapter is best-effort and requires live testing. This does not import or replace either addon's paging/layout configuration.

Opening current layout, casting in and out of forms, learning spells, respeccing, swapping ranks, action-bar paging, combat entry during work, and restoring defaults/backup must be exercised in Classic Era before claiming live-client certification.
