# Hot Swap 1.0 preset transfer review

Reviewed 2026-11-02. Scope: Presets.lua, Core.lua import dispatch/legacy parser, typed Library descriptors, existing Share UI, and profile regression tests. Actual Lua 5.1 modules executed against deterministic WoW mocks; this does not establish live-client clipboard or casting behavior.

## Findings and corrections

| Severity | Finding | Resolution |
|---|---|---|
| High | Import changed the selected preset and attached imported settings immediately, despite preserving live bindings. | Imports now add separately named drafts while retaining the selected preset, original settings table identity, preview, and dirty state when no new shortcut changes the plan. Retained imported shortcuts invalidate the cached plan and recompute unapplied status. Selecting and applying imported presets remains explicit. |
| High | A validation exception while adding imported shortcuts could leave a partially merged collection. | Validate shortcuts in an isolated copy of the preset collection; restore current references and publish the additions only after successful validation. Injected exceptions leave preset IDs, settings, collection and game controls unchanged. |
| Medium | Text-editor UTF-8 BOMs and surrounding whitespace could make downloaded profiles appear invalid. | Both KBO2 and legacy dispatch normalize BOM, CRLF and surrounding whitespace, with a raw input size ceiling before normalization. |
| Medium | The legacy parser accepted non-finite/negative mount settings and arbitrary invalid binding strings. | Validate finite positive integral mount IDs, nonzero spell mounts and normalized binding keys before merging. |
| Medium | Export-all could emit text beyond the importer limits. | Reject oversized exports with instructions to export selected presets separately; limits match 2 MB / 50,000 records. |
| Test gap | Round-trip tests relied on import selecting the result and could inspect the original after the behavior change. | Explicitly select imported drafts when testing their reconstructed settings. Separate regression tests assert import itself preserves the current draft. |

## Player behavior

1. In Import / export, export the selected preset or all presets. Select the text and copy it with Ctrl+C.
2. To distribute a download, paste the code into a plain-text editor and save as a UTF-8 `.hotswap` file.
3. To use a downloaded profile, open it in a text editor, copy its contents, paste into Hot Swap and choose Import presets. The addon has no operating-system file picker or arbitrary-file reader.
4. Imported names are added; collisions receive numbered suffixes and never overwrite local presets. Current character class must match KBO2 class metadata. Legacy KBO1 imports remain supported.
5. Current settings, selected preset and live bindings remain unchanged. The success message identifies a draft to select in Presets. Review and explicitly apply it when ready.
6. Conflicting preset shortcuts are left unassigned. Imported shortcut validation uses the same rules as interactive shortcut assignment. Imports perform no protected game writes.
7. Interchange contains typed settings and action descriptors, never executable Lua or macro bodies. Existing personal macros are referenced by local name/fingerprint and must exist locally to resolve.

## Verification

23 focused existing/new transfer and round-trip scenarios passed, including malformed input, class checks, local macro syntax rejection, item alternatives, fixed ranks/replacements, talent choice ordering, native-bar preferences, duplicate names, fresh IDs, UTF-8 files, preservation of current references, and injected shortcut-validator failures. Seven dedicated new `profile_transfer_*` regressions cover the newly corrected behavior. The subsequent combined release suite passed 481/481 scenarios in actual Lua 5.1 with mocked WoW APIs. Full-catalog transaction/identity fixtures explicitly opt into synthetic character macro capacity; real-client macro-capacity scenarios retain 30 slots.

The parser retains bounded input and record counts. It does not evaluate input. Tests establish addon behavior under mocks; the parent release review must record the final combined suite outcome and live-client user test limits.

## Test fixture migration for character-only macros

The retired `allowAccountMacros=true` option previously let full-catalog Druid transaction fixtures bypass the real character-bank limit. Those fixtures now call the explicit test-only `Mock:AllowFullCatalogMacros()` helper, which grants 150 synthetic character slots. This isolates rollback, identity/reordering, paging, UI, backup and ownership behavior from capacity. It is not a production capability or a claim that WoW permits 150 character macros.

Mock creation, counting, deletion/compaction and alphabetical bank reordering all use the declared bank boundaries. Fresh-VM SavedVariables reload testing recreates the same synthetic capacity on both sides of reload. Flavor was not changed because several fixtures intentionally exercise Forever focus and form capabilities.

Real-capacity coverage remains separate and uses 30 character slots: `macro_capacity_spec.lua`, `v1_engine_spec.lua`, full-bank preview/apply rejection, and named-backup restore preflight. The nine low-level Era class cases remain at the real cap. The bindings reviewer is adding the fully learned Era class matrix before final packaging. The full-bank tests explicitly reset both global and Constants character limits to 30, so the synthetic helper cannot accidentally weaken their assertions.

Combined verification after this migration: **481/481 passed**. The final package run may include further matrix tests added by the bindings reviewer; its result supersedes this intermediate count.
