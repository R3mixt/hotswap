# Hot Swap 1.0 design and interaction review

Reviewed 2026-11-02 against the requested player behavior. Source review covers UI.lua, LibraryUI.lua, SettingsUI.lua, HoverBindingsUI.lua, ItemsUI.lua and their model boundaries. Rendered evidence is generated by the actual Lua UI under the deterministic harness with substitute artwork and fonts; it is **not an in-game screenshot or proof of secure-client behavior**.

## Findings and fixes

| Finding | Impact | Resolution |
|---|---|---|
| Replacement and swap prompts were unconditional outside hover editing | Repetitive confirmations could not match the player's preference | Added independent character-local switches under Settings > Window, both on by default. They do not travel with presets. Apply and restore confirmation remain separate. |
| Native spellbook drops were ignored by the keyboard's receive-drag handler | Player expectation of dragging from Blizzard's spellbook failed | Added guarded spell cursor resolution, including old spellbook-index lookup. Uses the same staged, reviewed editing path as the built-in spellbook. Invalid payloads retain the cursor; accepted drops clear it. |
| The keyboard test mouse shield covered Blizzard's spellbook | Native spellbook could not be used while editing | Added Game spellbook button. While the native book is visible, the outside mouse shield is suspended, with an explicit normal-game-mouse-controls notice. It returns when the book closes. |
| “Restore original setup” could be mistaken for restoring Blizzard defaults | Players could not reset to an actual default layout | Added distinct Restore default keys action in Backups, with unconditional confirmation, backup-first engine operation and explicit action-bar preservation wording. |
| Account macro overflow contradicted the character-only requirement | Generated macros could consume shared account slots | Removed the account overflow control and replaced it with character-only explanation. Engine policy belongs to the binding-engine review. |
| Movement/camera discovery was not obvious | Bindable game commands could be overlooked | Retained the Game spellbook category system and added a specific tooltip naming movement, camera, targeting and interface commands. These use native binding commands, not generated macros. |
| A live destination could change while its replacement prompt was open | Continue could approve a different action from the one reviewed | Capture and revalidate the key command, live slot and slot contents before staging; reject a changed destination or combat transition. |
| Drop handlers lacked consistent source/modal/combat guards | An unexpected drag could enter an inappropriate editor context | All drops now reject recommendation-only contexts, open modals and combat. Native cursor reads are protected with pcall. |

## Verified behavior

- Opening always selects Current bindings, clears prior search/modifier inspection, refreshes the live reader, opens the built-in spellbook and uses Apply changes for pending current edits. External action-slot and binding events invalidate the live view. Existing regression tests cover reopening from a draft and live event refresh.
- Current editing affects only staged keys/slots. Draft editing remains a separate named preset; previewing a recommendation is not an apply operation.
- Drag from Hot Swap's spellbook or Blizzard's native spellbook. Current mode supports client-valid keys; game-protected primary mouse controls remain protected. Draft mode additionally enforces its movement/self-cast/form constraints rather than silently inventing unsupported assignments. “Any key” cannot include stand-alone modifier keys or controls rejected by the game API.
- Replacing a live action slot warns that other bindings sharing that slot are affected. A draft swap moves linked form positions together. Turning prompts off changes review frequency, not when gameplay writes occur.
- Game tab exposes the client's bindable movement/camera commands through categories/search. Available commands depend on the client; absent commands are not invented.
- Import/export help describes copy/paste text and opening a downloaded .hotswap text profile in an external text editor; no nonexistent in-game filesystem picker is advertised. Imported profiles must be reviewed in Presets.
- Recovery paths are distinct: named backup, original pre-Hot-Swap setup, and Blizzard default keys.

## Visual QA

`python ui-qa/capture.py` instantiated and captured 29 UI states successfully. `ui-qa/render.ps1` rendered those states. Inspected the Current keyboard with attached spellbook, Settings > Window, and Backups images, retained under `review/1.0-evidence/`. The new controls fit their panels without overlap or clipped labels at the baseline geometry. Existing window scaling tests cover fitting the combined editor to smaller viewports without overwriting the user's preferred scale.

Current mode has a clear source selector, live action-page label and distinct Apply changes action. The spellbook is adjacent to the keyboard, with sufficient separation between the list, drag instruction and native-book button. Settings labels explain scope. Recovery actions are grouped and explicitly differentiated.

## Regression coverage added

`tests/release_ui_spec.lua` covers local independent confirmation settings and reload persistence; native drag confirmation/cancel/accept; legacy book index resolution; rejection of invalid/nonspell payloads; combat/modal/recommendation guards; mouse-shield suspension/restoration; the native-book opening button; linked swaps with confirmation disabled; and unconditional defaults-reset confirmation. Tests assert zero protected gameplay writes during editing. `tests/review_crosscheck_spec.lua` adds changed-key, changed-slot and combat-transition confirmation regressions. These run against real addon Lua with mocked WoW APIs.

## Remaining client acceptance checks

Actual Classic Era rendering, Blizzard template font metrics, cursor payloads, spellbook layering, combat taint and action-bar-addon interaction require user testing in WoW. Verify native spellbook opening/closing, dragging known ranks to an empty and occupied key, confirming/cancelling and disabling both prompts, modifier layers and mouse controls, closing the addon during capture, entering/leaving combat, and restoring defaults followed by a named backup. The harness does not certify these secure-client behaviors.

Keyboard key tags remain small at the default density; larger user window scale is available. Labels and tooltips supplement color, but actual font legibility at very small UI scale remains a client acceptance item. Window fitting still recenters the editor when the spellbook changes; persistent manual positioning is a future ergonomic improvement, not a release correctness claim.
