# Hot Swap compatibility and verification

Status: initial implementation is exercised by an automated Lua 5.1 regression suite. The runner reports the current scenario count and results. Source/API research and mocked Lua tests do not establish in-game compatibility. Installation is recorded separately from automated validation. No live-client casting test has been performed.

## Target clients

- Primary: World of Warcraft: Forever 1.60.1, observed local installation build 70707.
- Secondary: Classic Era 1.15.9, observed local installation build 70576.
- Retail: compatibility mode with legacy anchors and learned-spell coverage; no complete Retail specialization optimization or live-client certification.

Use capability detection as well as client/build identification. Forever uses modern UI APIs despite its Classic-inspired gameplay. Do not assume Classic form indices, spell availability, spell ranks, bindings, or bar pages match Forever.

## Primary implementation evidence

- [Forever secure action templates](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_FrameXML/SecureTemplates.lua) expose spell, item, macro, equipment-set, target and focus action handlers. Current source also contains a `C_Macro.RunMacroText` path; this is not evidence that arbitrary addon-generated macro text is permitted in combat. Prefer stored compact macros and secure preconfigured buttons. Avoid macro chaining.
- [Forever macro capacity constants](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/MacroConstantsDocumentation.lua): 120 account and 30 character macros. [Macro UI XML](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_MacroUI/Blizzard_MacroUI.xml) limits the editor to 255 characters. Check capacity before any mutation.
- [Forever binding listener](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_Settings_Shared/Blizzard_Keybindings.lua) uses `SetBinding`, conflict inspection, modifier chords, wheel input names, and `SaveBindings(GetCurrentBindingSet())`.
- [Era's Vanilla binding definitions](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_FrameXML/Bindings_Vanilla.xml#L1144) explicitly comment out `FOCUSTARGET` and `TARGETFOCUS`; [Forever's Camelot binding definitions](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_FrameXML/Bindings_Camelot.xml#L1155) register both. Hot Swap reads the actual `GetNumBindings`/`GetBinding` registry, including unbound commands. The selected spell-catalog flavor does not grant a client capability.
- [Forever combat settings](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_SettingsDefinitions_Frame/Combat.lua) expose modified-click self-cast and mouseover settings. Generated friendly macros must explicitly put Alt/self before mouseover, since native secure-template mouseover handling can precede native self-cast checks.
- [Forever CVar API](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/CVarDocumentation.lua) requires writable public, nonsecure CVars for `SetCVar`. Check results; do not assume all UI settings are addon-writable.
- [Forever item API](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/ItemDocumentation.lua) and [container API](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/ContainerDocumentation.lua) support candidate scanning. A use spell does not establish that an unequipped item can be activated, that it is appropriate, or that its use is allowed in a particular activity.
- [Forever input API](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/InputDocumentation.lua) reports observed click/pressed states. No physical mouse model or hardware button-count enumeration was found. Calibration counts distinct inputs actually clicked; remapped keyboard events cannot identify physical hardware.
- [Era spell API](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_APIDocumentationGenerated/SpellDocumentation.lua) supplies display information by spell ID or name, including unlearned spells present in the database. Hot Swap keeps these display IDs separate from learned spell IDs used for secure actions.
- [Era frame API](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_APIDocumentationGenerated/SimpleFrameAPIDocumentation.lua) marks keyboard propagation changes as restricted. The input tester must release its input frames on combat entry without trying to change protected input settings during lockdown.
- [Forever panel templates](https://raw.githubusercontent.com/Gethe/wow-ui-source/forever/Interface/AddOns/Blizzard_UIPanelTemplates/Mainline/UIPanelTemplates.xml) provide the native BasicFrame window and inset. The configuration keyboard uses game action-slot artwork. Combat actions use Blizzard's original bars; there is no custom dock or secure form dispatcher.
- [Era ActionBarController](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_ActionBarController/ActionBarController.lua) owns native vehicle, override, bonus-form and manual page priority. [MultiActionBars](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_ActionBar/Shared/MultiActionBars.lua) defines extra-bar pages; [ActionBars settings](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_SettingsDefinitions_Frame/ActionBars.lua) uses GetActionBarToggles and SetActionBarToggles. The addon synchronizes available proxy-cache bits before a final complete toggle-array write, and detects extra frames rather than assuming every client exposes the same number.
- [Blizzard's addon restrictions explanation](https://worldofwarcraft.blizzard.com/en-gb/news/24246290/combat-philosophy-and-addon-disarmament-in-midnight) describes secret combat values. Optimization here means preparing a stable binding layout, not choosing a combat rotation or automating reactions.

## Required live-client checks before claiming support

The focus-capability correction addresses the reported Era failure when binding F6 to `TARGETFOCUS`. Unsupported untouched stock commands and focus variants are omitted. A saved explicit focus request fails with a clear error; it is never converted to current-target behavior. Spell and item target menus offer Focus only when the client's registry supports it. Generated focus layouts saved on another client are checked again before reactivation or named restore. Original snapshots and rollback still preserve personal macro and addon bindings without applying the stricter rules for newly planned commands.

Version 0.3.1 reproduces and fixes macro-bank reordering during Optimize. The current [proxy settings implementation](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_Settings_Shared/Blizzard_Setting.lua) and [action-bar setting cache](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_SettingsDefinitions_Frame/ActionBars.lua) also inform the visibility adapter: all supported cache bits are synchronized before the final complete mask, then the native bar controller refreshes from mirrored values outside combat. Retest Apply & save with extra bars initially hidden, then optional bars shown/hidden, and Restore. Native override/vehicle visibility remains owned by Blizzard.

Version 0.3.0 also addresses the user's Engine timeout during Apply & save and its automatic rollback. Apply, named restore, original restore and rollback now run through bounded frame jobs; binding scans and writes are split into steps, and progress is visible. The inactive binding-set read remains atomic so the player is never left on that set across frames. Failure-injection and large-binding-map tests verify rollback and bounded writes. Retest the actual client: these checks do not prove that every game API call can never time out.

1. Load on the exact target client with Lua errors shown; confirm version detection and complete learned-spell scan, including multiple ranks and passives.
2. Preview and apply out of combat with existing personal macros/bindings present; verify only planned changes, then reload and fully relog to check persistence.
3. Cast a mouseover heal with friendly target, hostile target, no target, dead target, and Alt held. Confirm Alt always wins and chosen fallback never silently spends a clutch cooldown on the wrong unit.
4. Test Base, Cat, Bear and Moonkin native pages. Confirm Prowl stays on Cat, and Travel/Aquatic use Base. Repeat a form button without dropping or recasting form. Test mobility, roots and heals from forms and verify intentional cancellation/re-entry. Learn a form or combination talent and confirm owned macros update outside combat without moving keys. Personal edits must not be overwritten by maintenance.
5. Enter combat and attempt apply, restore, item-preset change and layout change. Confirm setup remains staged and no protected writes, taint errors, or surprise rebinding occur.
6. Test all mouse buttons over world, unit frames and UI; test the wheel enabled/disabled and Alt+wheel camera zoom. Verify keyboard remaps and duplicate input warnings.
7. Test trinket slots 13/14, selected bag items, empty slots, async item loading, bag sorting, exhausted stacks, equip-required items and shared/equip cooldowns.
8. Restore with changed/deleted/user-edited macros present; confirm it does not delete unrelated macros and clearly reports anything it cannot safely restore.
9. Test action bar, stance, vehicle/possess and other override behavior where available, including interactions with common action-bar addons.
10. Check the configuration frame at the game's normal UI scale and a smaller display size: frame/title/tab artwork, text fit, selected/disabled states, scrolling, close/Escape behavior and input capture. Verify action-slot borders and readable key labels over active cooldowns. The geometry renderer cannot validate game texture availability or exact font metrics.
11. Open through the Escape menu and AddOns settings. Verify the entry appears once after repeated menu openings and does not apply changes. On the keyboard, inspect form and modifier layers, click actions, try a confirmed same-form swap, and verify incompatible collisions remain blocked. First Escape must finish mouse recording; only the next Escape closes Hot Swap.
12. In Bindings, press `1` and modifier combinations: key highlights and the action readout must change without casting. Verify key release, typing in search, mouse buttons/wheel, modal transitions, closing the window and combat entry all release input correctly. Test before and after Apply, and with both action-on-key-down settings. Native input delivery cannot be certified by the mock harness.
13. Check learned and unlearned spells for aligned icons and labels. Hover an unlearned spell for its native tooltip, bind it in advance, and confirm the reserved action becomes usable only when actually learned. Incomplete combination macros must remain inert. Missing item selections remain distinguishable from unlearned spells.
14. Create and duplicate full custom presets, give each a free mode shortcut, activate them outside combat and verify the entire old binding map is replaced. Check mouse camera/selection, Enter chat, Shift-Enter command chat, menus and screenshots after replacement. Confirm shortcuts survive renames, remain present in every mode and do nothing in combat.
15. Verify the named backup exists before every activation and restore. Restore both a pre-addon snapshot and a previous Hot Swap layout, including account and character binding sets. Stage changes, reload, and restore a snapshot with a newer draft present; the UI must continue distinguishing the active layout from edits not yet in use.
16. Export one preset and a full collection from Import / export. Copy to an external text file and import the text on another same-class character. Check duplicate-name preservation, class mismatch rejection, duplicate shortcut handling and unchanged live bindings until Apply & save. The addon does not create an arbitrary external file directly.
17. Open the miniature spellbook alongside the keyboard. Check specialization categories, talent markers and Show ranks. Drag and click-place entries on empty and occupied keys; cancel without leaving a custom action behind. Confirm a fixed lower rank and the highest-rank family can coexist and retain their keys after learning a higher rank.
18. Inspect target badges and exercise target, mouseover, focus and self modes only on eligible actions and supported clients. On Era/Hardcore, Optimize must finish without assigning `TARGETFOCUS`, creating focus utility macros, or offering Focus in spell/item menus. An imported explicit focus selection must stop before game writes; selecting the Forever catalog must not bypass that check. On a focus-capable Forever client, unbound focus commands and focus variants must remain available. Verify Alt-self precedence and non-self-targetable exceptions. Existing user macros must preserve their contents and require review if changed or missing. Import/export must preserve rank and target edits without executing text.
19. Apply and restore with original bar spells, macros, items and supported flyouts present. Verify native contents, visibility and manual page return. Put an item on the cursor before applying: the addon must stop without clearing it. Enter combat during a running job and verify honest pause/resume messaging.
20. In Settings, confirm logging starts disabled, opacity/scale update immediately, Reset appearance restores defaults, and the spellbook remains within the viewport. Enable logging, reproduce a setup problem, inspect full Details and View / copy log, then `/reload` and verify entries persist. Copy a long log using Ctrl+C; keyboard navigation must scroll to the cursor. Disabling logging must preserve entries until Clear log. Imports and preset switching must leave appearance/logging preferences unchanged.

Menu integration references Blizzard's [shared GameMenu implementation](https://github.com/Gethe/wow-ui-source/blob/classic_era/Interface/AddOns/Blizzard_GameMenu/Shared/GameMenuFrame.lua), [native pooled menu buttons](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_SharedXML/Shared/Frame/MainMenuFrameTemplates.lua), and [AddOns settings registration](https://github.com/Gethe/wow-ui-source/blob/forever/Interface/AddOns/Blizzard_Settings_Shared/Blizzard_Settings.lua).

The Lua 5.1 harness uses mock events and protected-action assertions. It cannot establish actual secure execution, server spell rules, protected hardware requirements, frame taint, input routing or rendered UI quality.

## Automated regression coverage

Tests are included in the separate source archive, not the game installation ZIP. From the extracted source root, run `python -m pip install -r requirements-dev.txt`, then `python tests/run_tests.py`. The local development workspace can also use its ignored `python-deps` directory. The addon itself has no dependency on Python or Lupa.

The suite executes the actual addon modules, not a rewritten optimizer. It checks all nine class catalogs, future reservations, rank and target macros, native page/slot mapping, extra-bar capacity, macro ownership, item selection, hardware alternatives, preset sharing, UI capture and staging. Transaction tests cover bounded writes, combat pauses, injected failures, original/named recovery, unsaved binding edits, and native action contents. A fresh-VM test carries SavedVariables and persistent mock game state through reload and verifies Restore still works. Native game dispatch itself is modeled, not executed inside WoW.

Command-capability regressions model the registered command inventory separately from assigned keys. They cover unavailable or partially readable registries, the 10,000-entry enumeration guard, unsupported explicit commands with zero writes, generated preset shortcuts, rejection of raw planned `CLICK`/`MACRO` commands, preservation of personal snapshot bindings, and named recovery of deleted presets with saved shortcuts.
